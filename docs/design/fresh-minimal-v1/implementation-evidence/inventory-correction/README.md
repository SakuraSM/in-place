# 原生库存页展示修复

日期：2026-10-27。截图来自 Android 原生调试包和隔离测试数据，代码与本目录证据一并纳入实现分支的 Git 版本管理。

## 复现与修正

| 复现条件 | 原因 | 修正 |
| --- | --- | --- |
| 同排混用长短名称、缺省分类 | 标题高度和分类行随内容改变，数量位置不齐 | 标题预留随系统字号缩放的两行空间，缺省分类显示“未分类”，数量靠底排列 |
| 两列卡片左右留白不同 | 百分比列宽与固定间距混用 | 每行两个等宽弹性栏位；单数尾项保留另一栏 |
| 照片地址非空但加载失败 | 原实现只检查地址，没有处理图片错误 | 平铺和层级复用图片回退组件，失败后显示分类插画或类型图标；替换地址后重新尝试 |
| 向上滚动库存 | 顶部安全区放在滚动内容内，会随内容离开屏幕 | 安全区移至固定页面壳，初始总间距保持一致 |
| 320dp 宽度、1.3 倍字号、长家庭名 | 家庭按钮无法收缩，把批量入口挤出屏幕 | 家庭按钮与名称按剩余空间收缩，保留完整批量入口 |

使用四条测试记录覆盖短名称、超长名称、未分类、长分类、失效照片、借出、损耗，以及数量 0 / 12345。失效照片使用保留域名 `example.invalid`。检查入口为库存页，关键词 `UI-Layout`，平铺展示。

## 验证结果

- Mobile ESLint 与 TypeScript 通过。
- Mobile 21 个测试套件、76 项测试通过。新增测试覆盖照片失败、替换照片、未分类记录、层级图片回退、固定安全区和沉浸式页面。
- 新增卡片、图片回退与结果布局文件通过 deterministic-frontend 单文件门禁。
- 模拟器实际检查了详情跳转、容器长按进入详情、批量选中与退出、单条筛选结果、四组尺寸与字号组合，以及资料表单弹出键盘后保存按钮仍可见。
- 最终冷启动后的当前应用进程没有 ReactNativeJS / AndroidRuntime 错误日志。
- 模拟器尺寸已恢复 1080×2400，字号恢复初始值 1.3。

第一轮遍历主要使用短名称与可加载图片，遗漏了上述卡片内部对齐和图片错误状态。本轮补查以混合内容和真实图片错误事件重现问题。切换系统字号时曾触发调试运行时的 Linking 重复初始化提示；四组最终检查均在独立冷启动后执行，未将提示出现时的首页截图计为库存通过。

本次证据限于 Android 模拟器。iOS 原生运行、真机和读屏未验收，未发布应用。
