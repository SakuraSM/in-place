# 全局设计规范

本规范适用于归位 Web、移动 Web 和 Expo 原生端的后续 UI 实现。当前交付为视觉稿；涉及原生行为的约定需要在实现阶段验证。

本文保留设计规格，运行时落地状态见[实现记录](implementation.md)。

## 设计方向

家庭库存整理应当轻松、清晰。使用暖白底色和深青色操作入口，沿用现有品牌标志与分类插画。页面先呈现用户当前要找、要看或要做的内容，再提供低频工具。

以留白、标题和行分隔组织信息。一个任务分组只用一层容器；普通列表不再为每一行嵌套圆角卡片。插画用于首页位置、分类和无实拍照片的对象，不在每一张设置卡里重复装饰。

## 色彩

| 语义 token | 色值 | 使用范围 |
| --- | --- | --- |
| canvas | `#F7F9F6` | 页面背景 |
| surface | `#FFFFFF` | 列表、表单和内容面板 |
| surface-muted | `#F0F5F1` | 缩略图与次级区域 |
| text | `#243B33` | 标题、正文、重要数字 |
| muted | `#61736A` | 日期、路径和说明 |
| brand | `#22735B` | 主按钮、选中项和链接 |
| brand-hover | `#195941` | 主按钮悬停与按下 |
| tint | `#E6F2E9` | 当前导航、选中标签和提示底色 |
| border | `#DBE4DD` | 容器、输入框和结构分隔 |
| warning / warning-tint | `#946019` / `#FBF2DF` | 到期、补货与需核对事项 |
| danger / danger-tint | `#AD403C` / `#FBECE9` | 失败、不可恢复操作 |
| info / info-tint | `#37677D` / `#EAF3F7` | 物品类型和中性说明 |

状态必须同时给出文字或图标。借出、在库、损耗以及对象类型各有文本，不以颜色代替含义。正文不得使用低透明度文字。白字只用于深色主按钮；浅薄荷色不承载白色正文。

## 排版

使用系统字体栈：Apple 系统字体、PingFang SC、Microsoft YaHei、sans-serif。原生端使用系统字体，不能照搬 Web CSS 字体栈。

| 层级 | Web | 移动端 | 字重 |
| --- | --- | --- | --- |
| 页面标题 | 30 / 39 | 26 / 34，首页 24 / 32 | 600–650 |
| 分组标题 | 19 / 27 | 17 / 24 | 600–650 |
| 正文、列表名称 | 14 / 22 | 14 / 22 | 400、600 |
| 字段标签 | 13 / 20 | 13 / 20 | 500–600 |
| 日期、位置路径 | 12 / 18 | 12 / 18，紧凑列表可 11 / 17 | 400 |
| 统计数字 | 32 / 42 | 28 / 36，首页紧凑统计 26 / 34 | 600–650 |

数字使用等宽数字特性，原生端使用 `tabular-nums` 对应能力。中文名称最多两行；路径可截断，但详情必须能读到完整路径。9–10 px 字号仅用于视觉稿编号和首页短统计标签等非正文内容，禁止用于表单、错误说明和主要操作。实现时应验证字体缩放后的布局。

## 间距、圆角与阴影

- 间距以 4 px 为基数，使用 4、8、12、16、20、24、32、40、48。
- Web 内容区横向留白 40，模块间距 24，面板内边距 24。
- 移动内容区横向留白 20，模块间距 20，面板内边距 18。
- 输入框与按钮圆角 12，内容面板圆角 20，移动面板圆角 16，标签圆角 6，筛选项采用胶囊形。
- 常规面板靠轻边框区分。阴影只用于浮层和短暂反馈，默认 `0 8px 28px #243B3309`。
- 原生端使用平台阴影与 elevation 适配，不把 CSS shadow 字符串传给 React Native。

## 布局模板

| 模板 | Web 组合 | 移动端组合 | 使用页面 |
| --- | --- | --- | --- |
| Dashboard | 固定侧栏 + 标题 + 概览 + 双列内容 | 顶栏 + 紧凑概览 + 单列内容 + 底部导航 | 首页 |
| Collection | 标题 + 搜索筛选 + 网格或列表 | 标题 + 搜索 + 横向筛选 + 两列或行列表 | 库存、分类、标签、提醒 |
| Split | 左侧选择或树 + 右侧内容 | 层级导航与内容纵向排列 | 位置、标签打印 |
| Map | 顶部筛选 + 画布 + 300 px 详情栏 | 紧凑统计 + 搜索 + 至少 330 px 画布 + 详情 | 地图 |
| Detail | 面包屑 + 图片资料双列 + 追踪信息 | 返回路径 + 图片 + 基本资料 + 后续操作 | 物品、位置、收纳 |
| Form | 最宽 720–760 px，必要字段优先 | 单列字段，固定底部保存 | 新增、编辑、密码、AI 配置 |
| Task | 任务概览 + 进度 + 清单 + 确认操作 | 单列任务，主操作靠近当前内容 | 盘点、连续归位、重复项 |
| Settings | 最宽 760 px，分组列表 | 相同顺序与命名，单列分组 | 我的、家庭、账户设置 |
| Auth | 品牌介绍 + 登录表单 | 简短品牌区 + 单列表单 | 登录、注册、接受邀请 |

不为每个页面建立独立的壳层。页面内容只决定标题、动作、数据和布局插槽，安全区域、滚动、导航和最大宽度由模板负责。

## 断点和适配

| 宽度 | 布局约定 |
| --- | --- |
| 小于 768 px | 单列；底部五项导航；不挤压桌面表格 |
| 768–1199 px | 收起为 72 px 图标侧栏；允许主辅栏改为上下结构 |
| 不小于 1200 px | 224 px 侧栏；主内容最大宽 1120；详情双列 |

本次 Web 稿固定在 1440 px、移动稿固定在 390 px 绘制。这些断点是后续应用实现规范，静态查看器的双端模式不是完整响应式应用。移动 Web 应复用移动布局；原生端需要额外处理安全区、软键盘、系统返回和权限对话框。

移动主导航严格保持「首页 / 库存 / 拍照 / 管理 / 我的」，位置树与地图通过管理中心进入。桌面导航使用同一份应用导航模型，增加高频位置与工具入口。二级页面高亮所属主导航，不另造一套底部导航。

## 组件复用

| 设计组件 | Web 现有入口 | 原生端现有入口 | 复用要求 |
| --- | --- | --- | --- |
| 页面壳与标题 | `shared/ui/PageLayout.tsx` | `Screen.tsx`、`PageHeader.tsx` | 同一宽度、间距和主次动作规则 |
| 分组容器 | 现有 SectionPanel / 页面 section | `SectionCard.tsx` | 面板只有一层，内部列表用分隔线 |
| 列表行 | 库存行与设置行 | `CompactListRow.tsx` | 名称、路径、状态和尾部动作固定插槽 |
| 状态标签 | `StatusBadge.tsx`、EntityBadge | `StatusBadge.tsx` | 类型和状态分离，统一语义色 |
| 分类插画 | 现有 categoryPresentation | `CategoryArtwork.tsx`、`InventoryIcon.tsx` | 共用 `packages/ui` 中的资源清单 |
| 内容切换 | `ContentTabs.tsx` | `ContentTabs.tsx` | 相同顺序、标签和选中态 |
| 表单字段 | 现有表单组件 | `FormField.tsx` | 标签、帮助、错误、必填统一 |
| 浮层和确认 | `ResponsiveDialog.tsx`、`ConfirmDialog.tsx` | `BottomSheet.tsx`、`ConfirmDialog.tsx` | 相同内容契约，平台独立焦点与返回处理 |
| 统计与任务状态 | `InventoryStatsGrid.tsx`、`EmptyState.tsx` | `MetricGrid.tsx`、`StateBlock.tsx` | 复用口径和语义，不重复计算统计 |
| 全局反馈 | `ToastProvider.tsx` | `ToastProvider.tsx` | 成功、失败、部分成功分别表述 |

Web 路径相对于 `apps/web/src`，原生组件相对于 `apps/mobile/src/shared/ui`。

共享的是设计 tokens、内容语义、导航配置、组件契约和资源。Web 与 React Native 分别渲染，不强制复用 DOM / View 实现。领域规则与请求编排仍留在 `packages/domain`、`packages/app-core`、`packages/api-client`，避免视觉组件承担业务规则。

本套源稿已使用 `primitives.js` 共享按钮、字段、列表、标签、提示、指标与图片资源，使用 `preview.js` 与 `layouts.css` 共享页面壳。后续落地应优先改造现有组件，不把静态 HTML 复制到每个业务页面。

## 控件和反馈

- 主按钮每个当前任务区域最多一个。次操作用描边或文字按钮。
- 标准按钮和输入框高 44–46 px。桌面紧凑按钮允许 36 px；移动端触控区域至少 44 × 44 px。
- 图标使用 Lucide，主要为 20 px、线宽 1.7；Web 和原生应统一图形含义，不要求图标库实现完全一致。
- 输入错误显示在字段下方并关联字段；不得只画红色边框。
- 表单必要字段在上；照片、价格、日期和标签为可选项。移动端优先折叠补充信息，实现时使用可展开分组。
- 保存前校验必要字段。保存中禁用重复提交；失败保留输入；成功反馈后再关闭或返回。
- 移动表单按钮避开安全区与软键盘；滚动区域底部预留操作条高度。
- 删除确认先显示对象名称和影响数量。取消为默认安全路径；确认按钮使用危险语义。
- 批量操作分别显示成功项和失败项，失败项支持单独重试。
- 加载使用骨架和文本，失败保留上下文，空状态给出一个明确的后续入口。
- 动效以 140–180 ms 透明度与轻位移为主。遵循 reduced-motion；不在列表加载时连续弹跳。

## 可访问性与待验收项

正文对比度目标为 4.5:1，大字为 3:1。`source/validate.mjs` 校验规范中的文本颜色组合，但不等于全页面 WCAG 审计。

Web 需具备主内容跳转、可见焦点、字段标签、对话框焦点管理、Escape 退出和合理 Tab 顺序。原生端需设置 accessibilityLabel、accessibilityRole 和状态，验证系统字号、TalkBack / VoiceOver 与焦点顺序。不能只靠截图判断这些要求已经通过。

本次已检查静态稿图片完整性、横向溢出及代表页面排版。React / Expo 运行、真实地图、摄像头、打印、备份导入、角色授权、读屏和真机安全区均属于后续实现验收。
