# 质量规则

这些规则适用于新增功能、修复、重构和文档维护。现有架构方向以 [目标架构](../architecture/target-architecture.md) 为准。

## 总原则

- 客户端不直接访问数据库；业务持久化经 `apps/server` API。
- `packages/db` 只负责 schema、数据库客户端和迁移，不承载页面编排。
- `packages/domain` 放稳定领域类型和规则；`packages/app-core` 放跨客户端应用逻辑；`packages/ui` 放共享 token 和原语。
- 不为“看起来复用”合并语义不同的状态、组件或模型。
- 先保护行为再重构；只清理触达范围，不扩大全仓 churn。
- 外部输入使用 `unknown`、schema 或类型守卫校验，不以断言代替校验。

## 禁止事项

| 等级 | 禁止项 | 说明 |
| --- | --- | --- |
| P0 | 前端新增直接数据库访问 | 必须通过 API 边界。 |
| P0 | 在前端或日志暴露密钥、令牌、安全密钥 | 包括 `VITE_*`、截图和错误详情。 |
| P0 | 仅靠前端隐藏按钮实现权限 | 授权必须由服务端校验。 |
| P0 | 无迁移修改持久化 schema | 需要 Drizzle schema、迁移和验证。 |
| P1 | 混合行为变化与行为保持型重构 | 必须拆分或明确说明。 |
| P1 | 用默认成功值吞掉认证、上传、AI、地图或备份错误 | 错误必须可观察且不伪造成功。 |
| P1 | 无影响分析修改共享包公共 API | 必须检查 Web、Mobile、Server 消费方。 |
| P1 | 无关格式化、批量重命名或锁文件 churn | 独立提交并说明。 |
| P2 | 为一次性需求创建空泛 `utils`、`helpers`、`common` | 优先使用领域命名和就近职责。 |

## Web 与 React

- 页面负责路由级编排；请求和可复用副作用放 Hook/service；展示组件保持可测试。
- 派生数据用纯函数或 `useMemo`，不要用 effect 同步复制状态。
- 请求、监听器、定时器和 SDK 实例必须处理取消、过期结果和清理。
- 对话框、表单、标签页、图标按钮和地图标记必须有语义、键盘路径、可见焦点和错误反馈。
- 响应式改动至少检查 1280×720 和 390×844，不以单张桌面截图作为完成证据。
- 地图、图片和类别图标使用真实资源或现有图标体系，不用临时 emoji/字符代替产品资产。

## Server 与 API

- 路由层显式校验参数、身份、家庭成员关系和角色。
- 错误响应不暴露堆栈、密钥、连接串、文件系统路径或第三方原始敏感响应。
- 外部 AI/地图请求必须设置允许列表、超时、响应大小或等价限制。
- 上传验证 MIME、大小和实际处理结果；生成的公开 URL 使用可信 `PUBLIC_ORIGIN`。
- 变更响应结构时同步共享 API 客户端、调用端和测试。

## 数据库与迁移

- schema 变更位于 `packages/db`，迁移文件纳入版本控制。
- 迁移应能在已有数据上运行；破坏性变更需要分阶段或恢复方案。
- 不在测试或脚本中默认连接生产数据库。
- 备份导入先校验版本、大小、结构、权限和事务边界，再写入。

## Mobile 与共享包

- Mobile 使用 `packages/api-client`、`domain`、`app-core` 中的共享契约，不复制一套分叉模型。
- 原生权限、安全存储、网络地址和平台差异必须通过适配层表达。
- EAS 构建依赖外部凭据；本地验证不能伪装成已经完成云端构建。
