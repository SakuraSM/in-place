# InPlace Harness 文档入口

本目录定义 InPlace 的工程 Harness：变更协议、质量规则、测试矩阵、现有门禁、任务路由、PR 模板、评分标准和维护记录。目标是让开发者和自动化 Agent 在改动前知道边界、改动后给出可复现证据，减少“能运行但不可排查”的交付。

Harness 只记录仓库内真实存在的入口和命令。当前尚未建设自定义增量验证脚本，不得在文档或交付材料中臆造不存在的命令。

## 阅读路径

- 开始任何改动：[变更协议](change-protocol.md)。
- 确认目录边界和质量规则：[质量规则](quality-rules.md)。
- 选择最小验证集合：[测试策略](testing-guide.md)。
- 提交或合并前确认本地与 CI 门禁：[门禁说明](guard-guide.md)。
- 按任务类型快速定位：[任务路由](skills.md)。
- 编写提交和 PR：[Commit Message](commit-message.md)、[模板](templates.md)。
- 评估 Harness 完整度：[评分标准](scorecard.md)。
- 记录稳定工程决策和缺口：[维护记录](records.md)。

功能设计与 UI/地图排障基线见 [Web UI 与地图功能设计基线](../product/web-ui-functional-design.md)。

## 基本原则

- 先写 Impact Map，再编辑代码。
- 客户端通过 API 使用业务能力，不能新增直接数据库访问。
- 行为变更和行为保持型重构分开说明、分开验证。
- 只修改任务触达范围，保留用户已有改动和未跟踪文件。
- 安全、权限、数据迁移、地图配置、备份导入和发布属于高风险变更。
- 文档中的命令必须能在仓库根目录按说明运行；未执行的验证必须明确写出原因。
